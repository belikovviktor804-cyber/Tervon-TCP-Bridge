# Tervon TCP Bridge — дорожная карта M5 и M6

**Актуализировано:** 2026-11-19  
**Источник истины:** [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)  
**Режим:** M4 закрыт оператором как PASS. **M5 STARTED (planning/setup); M6 HOLD / DISCUSSION_REQUIRED**. Документ не утверждает прохождение M5-проверок.  
**Очередь:** M4 PASS → **M5 active on `work/m5-linux-release`** → Linux v1.0.1 (only after release gates) → M6 Android **only after separate architectural discussion and approval**.

## Зафиксированное состояние перед M5

- Linux M4-кандидат исходного коммита `8d0aa3777c209d2825a1c11dfbae9487893cb7f5` установлен на **Homeserver и Finserver**. Оба оператора установки сообщили `M4_INSTALL=PASS_PROCESS_AND_SHA`, фактический SHA256 `5035217a89476117894efe1a44db5dcdd1242773d7fd9461170f2cf6ccb98a90`; исходные M3-бинарники и манифесты отката сохранены.
- После перехода обоих узлов на M4 оператор **прямо подтвердил «М4 готов. Работает. Можно закрывать.»**. M4 принят и закрыт как PASS в `M4_ACCEPTANCE.md`. Результат работающего VPN/Stats принят без повторных синтетических тестов; это не означает наличие новых количественных RTT/fairness измерений.
- M3 Padding/Jitter live-активация и двусторонние агрегированные счётчики ранее были подтверждены. Но количественные критерии **per-frame Jitter ≤4 мс и бюджет 20 мс/сек, RTT/fairness/длительная нагрузка** не были подтверждены индивидуальными измерениями; оператор разрешил перенести эти *release-blocking* доказательства в M5. Не объявлять их выполненными без данных.
- В старом журнале есть исторические FAILED/NOT_RUN до их исправлений и последующих PASS. При определении текущего статуса пользоваться **последним датированным результатом**, а не устаревшей строкой.

## M5 — измерения, интеграция, выпуск Linux v1.0.1

**Статус:** **IN_PROGRESS / M5.1 PLANNING** (ветка `work/m5-linux-release`; количественные и релизные проверки ещё НЕ НАЧАТЫ).\n\n**Назначение:** получить обоснованную готовность существующего Linux Bridge к одному релизу v1.0.1. Не переписывать работающее приложение, не расширять TCP scope до UDP/QUIC и не запускать длинные бессодержательные тесты.

| Шаг | Что входит | Проверка/результат |
|---|---|---|
| M5.1. Freeze baseline | Зафиксировать точные бинарники, commit, конфигурационные **параметры без секретов**, уже подтверждённые реальные TCP-маршруты и рабочие нагрузки на Homeserver/Finserver; использовать опубликованный v1.0.0 как контроль там, где сравнение безопасно и технически сопоставимо | Таблица происхождения v1.0.0 vs v1.0.1, целевые сценарии и оговорки; M3 rollback сохранён |
| M5.2. Functional integration | TCP VPN от клиента через Encapsulator → mTLS/TLS1.3 + HTTP/2 → Decapsulator → backend; двунаправленный byte-exact поток, короткие запросы, длительная ровная передача (видео), порционный поток и скачивание; проверить утверждённые рабочие VPN-конфигурации (VLESS, Trojan, Shadowsocks, OpenVPN-over-TCP) только там, где они реально доступны | PASS существующих проверенных маршрутов без изменения неиспользуемых протоколов; подтверждение оператора/скриншот, если этого достаточно |
| M5.3. Focused quantitative gate | Только ещё не доказанные величины: максимальная **фактическая** задержка Jitter на кадр и бюджет за окно (ориентиры 4 мс/кадр, 20 мс/сек из M3), fairness/отсутствие starvation, RTT p50/p95/p99, CPU/RSS, потери/ретрансляции по возможности и влияние краткого/длинного TCP-трафика. Проверить отсутствие счётчиков ошибок и зависших сессий | Чёткие «измерено / не измерено»; согласованные допустимые отклонения, сопоставимые условия. Не считать агрегаты доказательством per-stream Jitter |
| M5.4. Reliability and rollback | Использовать уже подтверждённые M4 CI на TLS/ALPN downgrade, timeout/cancellation, churn/session-drain; для оставшихся реальных отказов — **точечные** проверки и доказанная возможность восстановления старого бинарника. Не разрывать работающий маршрут ради повторения уже доказанного без причины | Запись результата, границ применимости и доступных rollback-артефактов |
| M5.5. Release package | Зафиксировать окончательный source commit и воспроизводимые Linux-amd64 binaries, проверенный SHA256SUMS и BUILD_INFO, JSON-конфигурации **без секретов**, документацию, release notes, известные ограничения, поддержку обновления/отката | Контрольные суммы совпадают, CI проходит на релизном commit, документы согласованы |
| M5.6. Publish | Выпустить **один GitHub Release v1.0.1** после закрытия всех обязательных критериев | Тег/артефакты релиза доступны, версия и SHA проверены; только теперь статус RELEASED |

**Правила выполнения M5:** короткие подтверждения действующей функциональности принимать по словам оператора/скриншоту. Измерения запускать лишь для реально открытых количественных требований и наименее инвазивным методом; не подменять их «VPN открывается». По одному логическому пакету: реализация (если нужна) → тест → исправление → подтверждённый PASS → GitHub документация/коммит. Не изменять рабочие nginx, Stats, x-ui, систему VPN или конфигурации без отдельного решения.

**Критерий закрытия M5:** реальные рабочие TCP-направления подтверждены, нет необъяснённой регрессии по сравнению с сопоставимым baseline, количественные release-blocking требования либо доказаны, либо явно пересмотрены оператором, release notes/JSON/SHA256SUMS готовы, **GitHub Release v1.0.1 опубликован и проверен**.

## M6 — Android TervonVPN, строго после M5

**Статус:** **HOLD / DISCUSSION_REQUIRED / NOT_STARTED**. Ни один подход к интеграции Android ещё не утверждён; технический перечень ниже — темы для обсуждения, а **не поручение на реализацию**.\n\n**Назначение:** в будущем подключить проверенный Linux Bridge к Android VPN-приложению, сохраняя действующие протоколы/ядро и поведение VpnService. M6 — **не часть условий публикации Linux v1.0.1**.

| Шаг | Что планируется | Проверка/результат |
|---|---|---|
| M6.1. Android audit | Проанализировать текущие TervonVPN `VpnService`, сетевое ядро, жизненный цикл сервиса, разрешения, существующие туннели и формат профилей; определить совместимый поддерживаемый способ повторного использования Bridge | Схема интеграции и риски; без замены текущего APK |
| M6.2. Integration design | Выбрать один поддерживаемый способ встраивания/связи с Bridge с учётом Android ABI, ресурсоёмкости и поддержки; при необходимости выделить интерфейс между Android и проверенным транспортом, не копировать протокольную/криптографическую реализацию вручную | Утверждённый дизайн и тестируемый интерфейс; без дублирования TLS/HTTP2 |
| M6.3. Key and route safety | Android Keystore/поддерживаемое защищённое хранение, корректное обращение с TLS/mTLS идентичностями, `VpnService.protect()` для внешнего Bridge-сокета во избежание VPN-loop, контроль утечек маршрутов и ошибок | Проверки секретов, защищённого сокета, отказа и корректного освобождения ресурсов |
| M6.4. UI/opt-in | Настройка профиля и переключатель **«Обход DPI»** для работы через Bridge, только осознанное включение; понятные причины отказов, сохранение поведения существующих VLESS/Hysteria2/других протоколов | UI и конфигурационная совместимость, выключенный режим не меняет прежние подключения |
| M6.5. Mobile lifecycle | Мобильная сеть ↔ Wi-Fi, смена IP/сети, временная потеря связи, переход приложения в фон, восстановление и завершение VpnService, работа с батареей/ресурсами; отладочные и реальный Android-аппарат | Повторяемые тесты под конкретные риски, отсутствие VPN-loop, незакрытых сокетов и критических регрессий |
| M6.6. Android release decision | Проверка приложения/подписи/версии/совместимости и план отката; публикация APK **только отдельным решением** | Установленный и проверенный кандидат, отдельно от Linux v1.0.1 |

**Границы M6:** не обещать побайтно неизменное перенесение Linux бинарника на Android без архитектурного аудита; не реализовывать собственную криптографию или TLS вместо поддерживаемых механизмов. Не заменять действующий APK, не затрагивать Android-подписывающие ключи и рабочие VPN-серверы без согласованного этапа. QUIC/UDP и новые протоколы не включены в текущий TCP Bridge.

  -> only after operator's architecture decision: Android audit
  -> safe Bridge integration, opt-in UI, Keystore and protect()
